# Competitor comparison and implemented improvements

Reviewed October 20, 2026. This is a comparison of published product pages and the local DemoPop implementation, not a hands-on evaluation of competitors' paid applications. Prices and marketing claims are not evidence of customer willingness to pay.

## What the comparison showed

| Product                                                  | Published strength                                                                                    | Implication for DemoPop                                                                                                                         |
| -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| [Tella](https://www.tella.com/)                          | Recording, editing, and sharing in one workflow; finished examples demonstrate the output.            | Show a real playable export at the point of creation. Keep the route from preview to editing obvious.                                           |
| [Screen Studio](https://screen.studio/)                  | Automatic zoom, framing, motion, and sound for screen recordings.                                     | Preserve DemoPop's automatic motion and framing. Ask for an intended use, rather than requiring motion design decisions before a result exists. |
| [EasyVeo Launch Video](https://easyveo.com/launch-video) | Real website screenshots, a free preview of creative directions, and payment after the film is ready. | A personalized review before purchase is a competitive baseline. | [Supademo](https://supademo.com/)                        | Interactive demos, guides, video, and buyer-facing sharing.                                           | Keep DemoPop's existing agency delivery workflow prominent. Interactive product walkthroughs would be a separate product investment.            |

The implementation priority is an inference from those pages and the code: make the first result credible and editable before asking for money. DemoPop's useful focus is a website-to-launch workflow for agencies, with existing reusable recipes, client folders, review links, and nine-video packages. The research does not establish that DemoPop is superior to these products or that its current prices are validated.

## What changed

1. **A saved website preview before paid export.** Signed-in users can capture a website, see its actual animated composition, and edit its copy without a purchased package. Captures remain private and ownership checked. The preview does not queue a worker render or consume purchased access. The first successful export queue operation still uses the existing atomic billing enforcement.
2. **Three useful starting directions.** Website launch preserves published website copy. Feature spotlight starts with the captured feature detail and changes the opening. Client reveal supplies a reveal opening. These remain editable and do not invent performance claims or pretend to show a historical before state.
3. **Review and edit in the creation flow.** Opening, three scene captions, call to action, client folder, format, and length feed the existing Remotion preview. The full studio remains available for scene/media/crop work. Opening the studio or starting another website saves valid edits first; a failed save leaves the current draft in place.
4. **Payment and connection recovery.** A payment prompt follows a successful project save. Reloading restores the same draft and refreshes owned media access. Media load retries reuse the project rather than recapturing the website. A failed draft read disables duplicate submission and offers retry, studio recovery, or a new website. Short-lived media URLs are not persisted in browser storage.
5. **Actual proof on first visit.** The creation page plays the real Orbit sample export, clearly labeled fictional. Its displayed length and aspect ratio describe that sample, not the user's unrendered settings. Completed cloud exports report format and duration from their immutable render snapshots.
6. **Mobile workspace.** Story and motion views have direct toggles, an export action beside the preview, and layouts checked at 390px and 320px. Preview controls retain readable contrast.
7. **Consistent selling language.** The homepage explains preview before paying; pricing explains account requirements and when a package activates. Billing links back to the video flow, which restores the reviewed draft in the same browser tab.

## Verification and limits

The server fixture executes the actual capture normalization, asset registration, project persistence, and preview branch against intercepted service HTTP responses. It verifies owned asset references, authentication before capture, and no billing/access/queue calls for previews. Browser fixtures verify live composition readiness, copy edits, saving before export, payment recovery, reuse of captured assets, retry/reload behavior, actual result dimensions, studio handoff, and mobile layout. Existing database tests cover atomic paid queue enforcement.

The preview requires the existing configured Supabase service and account. It uses the existing capture limits: six attempts per account per hour and two concurrent captures per web process, with existing network/capture bounds. Rate limiting is not a permanent free storage allowance. Actual captures depend on the target site's accessibility.

Live Supabase/Stripe/worker acceptance remains the deployment checklist in [commercial implementation](DEMOPOP_COMMERCIAL_IMPLEMENTATION.md). ## October 23: review the entire launch package before rendering

A fresh review of official pages found that [Tella](https://www.tella.com/pricing) offers a broad recording/editing/sharing workflow; [Screen Studio](https://screen.studio/) adapts framing and captions to aspect ratios and previews social app overlays; [EasyVeo](https://easyveo.com/launch-video) delivers landscape and vertical website films; and [LaunchReel](https://launchreel.ai/) promotes editable shots, versions, and caption exports. These are published capabilities, not verified results from their paid applications. Search snippets and opened pages disagreed on some prices, so this follow-up does not rely on price comparisons. The earlier EasyVeo preview/pricing description above reflects the October 20 review and should not be treated as current pricing.

The code audit exposed a practical weakness in DemoPop's existing nine-video package: users could edit three hooks but preview only the main film, and a scene's single crop applied to every output shape. The chosen improvement is an inference from the product workflow: make the entire deliverable inspectable and preserve intentional framing for each format.

- **Nine live versions:** Preview launch package opens format and hook selectors above the existing player. It uses the same `packageVariants()` function as the worker. Selecting versions pauses and seeks to their opening, without queuing renders, changing the main film, or adding undo entries. Return to the main film restores its format and opening. Restoring a recipe/draft, importing a website, or moving through edit history exits package preview.
- **Independent story framing:** Each product-story scene can keep separate vertical, landscape, and square crops. The selected format's thumbnail, player, individual export, and package render share the same crop resolution. Older scenes retain their shared crop until a format is adjusted. Resetting one format preserves the other overrides; Apply framing to every format explicitly replaces the shared crop and clears overrides.
- **Direct editing handoff:** Edit [format] framing switches the editor's active format, opens the first scene's framing controls, and focuses its first slider. This is an editing action and can mark the draft changed; browsing package previews alone cannot.
- **Recoverable work:** Browser drafts, recipes, saved project JSON, immutable export snapshots, and package manifests retain the optional crop settings. Slider drags group in Undo by scene and format. No database migration is required. The web application and export worker must run matching source versions before using the new settings, since an older worker's strict schema does not accept the added scene property.

Verification artifacts are written to `out/qa/package-preview/`. Configured browser tests use intercepted account APIs; no live service calls, payments, deployment, or commits are part of this change.

Final follow-up checks: **61 unit/integration tests passed**, **13 local editor/workspace browser checks passed across the final suite and focused rerun**, and **all 27 configured-account browser checks passed**. The desktop assertion was scoped to the video canvas after editable multiline hook fields introduced a second matching copy string. TypeScript, ESLint, formatting, and `git diff --check` passed. `npx tsx scripts/inspect-format-framing.ts` produced nine actual Remotion PNGs and verified decoded pixels: active-format framing changes the output in each of the three formats, while an override for another format preserves identical output. These are local renderer and intercepted-service UI checks; hosted web/worker acceptance remains outstanding.
